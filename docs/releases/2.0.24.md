## What changed

**The notice 2.0.23 added is now readable.** It shipped as an empty yellow
box: the text was in the page, correct and complete, in near-white on Ant's
cream warning background — a contrast ratio of 1.03. It is 10.1 now.

**Updating the web interface no longer leaves the browser on the old one.**
The build had stopped giving changed files changed names: the whole app's CSS
was appended into the `vendor` chunk after its content hash was computed, so
two builds with different styles both shipped as `vendor-BefK_L50.js`, and
the firmware serves `/assets` with a thirty-day cache. A browser that had
visited the miner before kept the old copy across an update. Because
scoped-style ids come from component source, the cached stylesheet's
selectors no longer matched the new markup, so components lost their styling
outright — an update that appears to do nothing, or to break the interface.
CSS is a separately hashed file again, `index.html` is `no-cache`, and the
`vendor` chunk's name changes on this update, so a stale cache is left behind
without needing a hard refresh.

If you have ever updated this interface and thought nothing happened, this is
the most likely reason, and it is worth reloading once after installing.

**The Settings page reports a web version that moves.** It is hand-written
and was not bumped for the web-only 2.0.23, so the field that tells you the
interface changed read the same before and after. Now 1.5.9 20260906.

**The login screen no longer claims the miner is broken.** Sitting at it
raised "data synchronization failed, please check the service", because the
API layer rejected with a bare string and the status poll's check for a 401 —
a session that needs signing in, not a fault — saw `undefined`.

## Still open

**The fan-fault protection cannot fire.** The flag that would trigger it is
never set, so a stalled or failed fan will not by itself shut the miner down.
The over-temperature trip and the unreadable-sensor trip are the two thermal
protections known to work.

**A BC04 cannot de-energise its own hashboard once the I²C bus is gone.**
A miner showing an empty bus scan, a board temperature of −60 °C, or a reboot
every four minutes should have its power removed by hand.

**The dashboard chart is not device history.** The hashrate, temperature and
power series live in the browser's `sessionStorage` and are appended by the
open page; the firmware keeps no history and serves no endpoint for it. Close
the tab and the chart starts empty, and a miner that ran all week with nobody
watching has nothing to show. Unchanged in this release, and not a small fix:
it needs storage on the device and an endpoint to read it back.

## Testing

Installed over the air onto a BC01 and checked on the running miner: both
images, the reboot, the rollback confirmation, mining resumed, and every page
of the interface. No BC04 has run this firmware — the BC04 images are built
from the same source and are untested on hardware.

## Files

`-full.bin` is the whole flash and is what the web flasher writes over USB.
`-ota.bin` and `-www-ota.bin` are for updating in place. `SHA256SUMS` covers
every file here; check it before you flash something you downloaded.
