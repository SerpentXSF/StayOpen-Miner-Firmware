## What this release is

**One fix, carried on top of 2.0.27 and nothing else.**

The core-voltage cap on a BC04 did not hold, and every released version up to
and including 2.0.27 is affected. This exists so that fix can reach owners
without waiting on 2.0.28, which is held pending hardware that can test the
rest of it.

If you are already running 2.0.28 or later, you do not need this.

## The core-voltage cap holds now

The vendor caps a BC04 at 4.80 V across four BM1370s in series. That cap was
applied to the startup default and nowhere else, while `TPS546_VOUT_MAX` on
the same board is 5.20 — and every other path checked against *that*.

The practical effect: **the core voltage box in the settings page accepted
5.20 V and the firmware applied it**, storing it as the value the miner comes
back up on. That is 1.30 V a chip against the 1.16 V the vendor currently
ships. It was three clicks deep in the web interface, not a hidden API.

One NVS key did the same thing through the boot-mode path.

Whether 1.30 V a chip harms a BM1370 is not something this project can answer,
and nothing here claims it does. That a cap existed and did not hold is
answerable. There is now one ceiling and all five sites ask it.

The settings page no longer offers a number the firmware will refuse, and its
reference marker has come down from 4.90 V — which sat *above* the vendor's
own cap — to the 4.65 V they actually ship.

## What is deliberately not in here

Everything else from 2.0.28. In particular `power_off_hashboard()` still
reports success whether or not the power actually went off; that fix is real
but it touches every protection path, and the point of this release is to
change as little as possible.

## Testing

**Built clean for BC01 and BC04. Not verified on hardware.**

The ceiling is a no-op on a BC01 by construction — `device_core_voltage_ceiling()`
clamps only BC04 and BC08 — so a BC01 cannot demonstrate the fix, and no BC04
is available to this project. An attempt to flash a BC01 as a regression check
was rolled back by the bootloader and is not counted as a test.

What the change can do is refuse a value it previously accepted. It cannot
raise a limit. A board already configured above 4.80 V will be brought down to
it.

## Files

`-full.bin` is the whole flash and is what the web flasher writes over USB.
`-ota.bin` and `-www-ota.bin` are for updating in place. `SHA256SUMS` covers
every file here; check it before you flash something you downloaded.
