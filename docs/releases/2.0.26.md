## The binaries no longer carry a blob we have no source for

Releases 2.0.4 through 2.0.25 linked `liba.a`, a prebuilt archive with no
source, into every BC01 and BC04 image — while `README.md`,
`docs/ASIC-ABSTRACTION.md` and `docs/FINDINGS.md` all said the BM1370 path was
free of it. Those documents were wrong for a year of releases.

`lt0051.c` is the only caller, and no BC board ever runs it: the dispatch arms
it sits behind are chosen by device model, and no BC board reports an LT0051
part. But a linker resolves references, not reachable calls, so compiling the
file was enough. Eighty-two sections of that archive sat at live flash
addresses in every published image.

A GPL release that conveys object code with no corresponding source is the
same defect this project raises against the vendor. It has been fixed rather
than explained away: the driver is behind `CONFIG_STAYOPEN_ASIC_LT0051`, off
by default, and the link map now holds one `LOAD` line with no member taken
from it, on both boards. The image is 20,608 bytes smaller.

Found by an external review of the link map, not by us.

## A crash that would have found you eventually

The reject-reason tally was bounded with `sizeof()` on an array of ten
structs, giving a limit of 680 rather than 10. The eleventh *distinct* reject
string overwrote the count with the first bytes of the message and the sort
that follows then ran over roughly half a billion elements.

Eleven distinct strings sounds unlikely until you mine on a pool that puts the
job id in the reject reason, at which point every stale share is a new string.

## Two endpoints answered anyone who asked

`GET /api/system/wifi/scan` returned the list of nearby networks to anyone on
your LAN, and `POST /api/theme` wrote settings with no authentication at all —
a page open in your browser could rewrite your theme without credentials.
Both now require a session. The theme *read* stays open; the interface needs
it before you sign in.

## The interface is legible again

The pending-restart banner was light text on Ant's cream warning background,
contrast 1.03 — present in the page and invisible on screen. The Quick Select
box was the opposite: Ant's stock black placeholder on a near-black
interface, contrast 1.05, so the control looked empty rather than ready.

Measured on a running miner afterwards: 10.1 and 7.86, and nothing else on the
page below 3. Alert and tag colours now live with the other Ant corrections
instead of in one component, because the seven other alerts in the interface
appear only on a fault — they were unreadable exactly when they had something
to report.

## Still open

**The fan-fault protection cannot fire.** Worse than previously stated: the
check is passed a maximum speed of zero and both its comparisons are against
that, so it returns true for any RPM including zero. Enabling the flag alone
would change nothing. The over-temperature and unreadable-sensor trips are the
two thermal protections known to work.

**A BC04 cannot de-energise its own hashboard once the I²C bus is gone.**
A miner showing an empty bus scan, a board temperature of −60 °C, or a reboot
every four minutes should have its power removed by hand.

Both are in `docs/KNOWN-ISSUES.md` now, which is where they should have been.

## Testing

BC01 only, over the air: both fixed contrast cases measured on the running
miner, and the firmware built and linked clean on both boards with the map
checked for the blob. **No BC04 has run this firmware.** The BC04 images are
built from the same source and are untested on hardware.

## Files

`-full.bin` is the whole flash and is what the web flasher writes over USB.
`-ota.bin` and `-www-ota.bin` are for updating in place. `SHA256SUMS` covers
every file here; check it before you flash something you downloaded.
